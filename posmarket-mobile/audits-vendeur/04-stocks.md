# Stocks (Inventory) — spec mobile (parité web)

> Référence = page Stocks du vendeur web, rendue à largeur mobile (< 768 px).
> Fichiers : `src/views/InventoryView.tsx` (1869 lignes), `src/components/inventory/VariantMatrixEditor.tsx`, `ImportProductsModal.tsx`, `ExportProductsModal.tsx`, `TransferProductsModal.tsx`, `src/components/ConfirmationModal.tsx`, `Button.tsx`, `Skeleton.tsx`, `ProductImage.tsx`, `src/app/(app)/inventory/page.tsx`.
> Règle de lecture : classe sans variante = mobile ; `hidden md:*` / `hidden sm:*` = desktop → EXCLU ; `md:hidden` = mobile → INCLUS ; `text-[9px] md:text-[11px]` → 9 px.
> Rien ne doit être inventé : tout élément absent de cette spec ne doit pas apparaître dans l'app.

## Données attendues (props + fournit par src/app/(app)/inventory/page.tsx)

- `page.tsx` (serveur) : session Supabase (`supabase.auth.getSession()`) ; si pas de session → `null` ; `getEffectiveStoreId(supabase, session)` ; si aucune boutique → `<NoStoreFound />` ; sinon `fetchStoreData(storeId, undefined, { orders: false, customers: false, invoices: false })` → `{ products, subscription, store }` ; puis `getPermissionsForUser(supabase, session.user.id, storeId)` → `{ permissions, role }`.
- Props de la vue :
  - `products: Product[]` : jusqu'à 200 produits de la boutique, enrichis `rating` / `reviewCount` (table productStats) ; `price`, `originalPrice`, `wholesalePrice` convertis en nombres ; `isOnline` normalisé à `true` sauf `false` explicite.
  - `permissions: StaffPermissions` : `canManageInventory`, `canManageCustomers`, `canManageOrders`, `canViewReports`, `canManageInvoices`, `canManageSettings`, `canManageStaff`. **Seul `canManageInventory` est utilisé** dans cette page.
  - `currentStoreId?: string` : indispensable en pratique (tous les appels serveur le passent ; `''` si absent).
  - `userRole?: StaffRole` : **non utilisé** par la vue (`'SUPER_ADMIN' | 'OWNER' | 'SELLER'`).
  - `subscription?: UserSubscription` : `{ tier, duration, status, startDate, endDate }` ; sert au plafond de produits via `getSubscriptionPlan(tier).features.maxProducts` (STARTER 50, PRO 500, ENTERPRISE 999999, défaut 6 si inconnu).
  - `businessType?: BusinessVertical` : défaut `'shopping'` ; pilote le badge d'en-tête (« Flux Shop » / « Flux Resto »), les onglets de flux, la taxonomie de catégories, et l'affichage de « Unité de vente » + « Tarifs de Gros / B2B » (shopping uniquement).
  - `storeName?: string` : défaut `'Boutique'` ; utilisé dans les modales export/import/transfert.
- Champs produit exploités : `id`, `name`, `price`, `stock`, `unit`, `category`, `mainCategory`, `businessType`, `isOnline`, `image`, `images[]`, `description`, `wholesalePrice`, `wholesaleMinQty`, `wholesaleTiers[{ minQty, price, unitPrice? }]`, `deliveryTime`, `preparationTime`, `options[]`, `variants[]`, `rating`, `reviewCount`.
- Formatage : `formatCurrency` = nombre entier tronqué + espaces de milliers + « FCFA » (ex. `12 345 FCFA`) ; `formatNumber` = « 1,2K » / « 3M » pour les compteurs d'avis.
- Mobile : les server actions n'existent pas en React Native ; prévoir des endpoints API équivalents (l'app possède déjà `src/api/client.ts` : `API_BASE_URL`, cookie de session, en-tête `X-PosMarket-Client: mobile-app`).

## Structure mobile (dans l'ordre)

1. **Toasts (succès / erreur)** — en haut de l'écran, alignés à droite (web : `fixed top-4 right-4`), z-200. Succès : fond `green-600`, Erreur : fond `red-600` ; texte blanc. Conteneur : padding 24 px / 16 px, radius 16, ombre forte, contenu en ligne : pastille ronde `bg-white/20` (icône `Check` 20 px, ou `AlertCircle` 20 px) + message `text-sm` gras. Durées : succès 3 s (4,5 s pour import et transfert), erreur 4 s. Textes exacts : message d'action, vides par défaut.
2. **Barre d'actions groupées flottante** — visible si ≥ 1 produit coché ET `canManageInventory`. Positionnée en bas, centrée (web : `fixed bottom-6 left-1/2 -translate-x-1/2`), largeur auto max 95 % de l'écran. Fond `slate-900/95` + léger ring blanc 15 %, radius 16, padding 16 px / 10 px, ombre forte, contenu en `flex-wrap` avec `gap-2`. Éléments, dans l'ordre :
   - pastille ronde 24×24 `bg-brand` texte blanc : nombre de sélectionnés (`text-xs` très gras) ; **le mot « sélectionné(s) » est masqué en mobile** (`hidden sm:inline` → EXCLU) ;
   - bouton « X » (icône 14, padding 4, texte `slate-400`) : vide la sélection (désélectionner tout) ;
   - séparateur vertical blanc 10 % ;
   - bouton « **Exporter (N)** » : icône `Download` 14 orange, fond `white/10`, radius 12, padding 12/6, `text-xs` gras ;
   - bouton « **Images (N)** » (web) / icône `Image` (mobile) : télécharge les photos des produits cochés (même style) ;
   - bouton « **Transférer (N)** » : icône `ArrowRightLeft` 14 bleue, même style ;
   - bouton « **Supprimer (N)** » : icône `Trash2` 14, fond `red-500/20`, texte `red-300`, bordure `red-500/30`, même dimensions.
3. **En-tête de page** (padding 12 px) : titre « **Inventaire** » (`text-xl` très gras, gris 900) suivi d'un badge de flux : « **Flux Shop** » (fond `orange-100`, texte orange brand) ou « **Flux Resto** » (fond `amber-100`, texte `amber-800`) — `text-[10px]` très gras majuscules, radius 8, padding 10/2. Le compteur « • N référence(s) » (`hidden sm:inline`) et le sous-titre « Gérez vos produits, vos stocks et vos transferts inter-boutiques. » (`hidden sm:block`) sont **EXCLUS** (desktop).
4. **Groupe d'actions** (sous le titre, en `flex-wrap`, justifié entre les bords) :
   - carte blanche bordure `gray-200/80`, padding 4, radius 16, ombre légère, contenant 3 ou 4 boutons `text-xs` gras padding 12/6 avec icône 14 : « **Exporter** » (`Download`, gris), « **Images** » (`Image`, gris), « **Importer** » (`Upload`, gris), « **Transférer** » (`ArrowRightLeft`, bleu : texte `blue-700`, icône `blue-600`). Séparateurs : traits de 1×16 px `gray-200`. En mobile, la rangée d'outils passe sur deux lignes (`flexWrap`, `flexBasis: 47 %`). « Exporter » et « Images » toujours visibles ; « Importer » et « Transférer » seulement si `canManageInventory`.
   - deux boutons pleins, visibles si `canManageInventory` : « **+ POS** » (fond `blue-600`, texte blanc, radius 16, padding 14/8, `text-xs` gras, icône `Monitor` 15, ombre bleue) et « **+ Store & POS** » (fond orange brand, icône `ShoppingBag` 15, ombre orange).
5. **Conteneur de liste** : carte blanche, bordure `gray-100`, radius 24, ombre légère, en colonne (occupe le reste de la hauteur, la liste défile en interne).
6. **Onglets de flux (verticaux)** — rangée de 2 boutons, défilement horizontal si besoin, `gap-2`, sans barre de scroll. Libellés exacts : « **Tous les flux** » (icône `Package` 16) puis, selon la boutique, « **Shop** » (icône `ShoppingBag` 16, couleur orange) ou « **Resto** » (icône `Zap` 16, couleur jaune). Style : `px-4 py-2.5` (16/10), radius 16, `text-xs` gras, bordure 2 px. Actif = fond blanc + bordure colorée (orange 500 pour Shop, jaune 500 pour Resto, gris 500 pour « Tous les flux ») + texte coloré + ombre légère ; inactif = bordure transparente, texte `gray-400`. Valeur par défaut : « Tous les flux ».
7. **Sélecteur de canal (segmented)** — conteneur `bg-gray-100`, padding 2, radius 8, `w-fit`. 3 boutons `text-[10px]` gras, `px-3 py-1.5` (12/6), radius 6, libellés exacts : « **Mode Mixte** » (défaut), « **POS Uniquement** », « **En ligne (Store)** ». Actif = fond blanc + texte `gray-900` + ombre légère ; inactif = texte `gray-500`.
8. **Barre de recherche** (padding 12, bordure basse `gray-100`) :
   - champ occupant la largeur (max 448 px) : icône `Search` 16 px grise à gauche ; **spinner** `Loader2` 16 px orange animé à droite pendant un chargement ; champ `pl-9 pr-4 py-2` (36/8), fond `gray-50`, bordure `gray-100`, radius 8, `text-xs`, placeholder exact « **Rechercher...** », focus = ring orange 20 %.
   - la bascule liste / grille (`List` et `LayoutGrid` 18 px, `hidden md:flex`) est **EXCLUE** : en mobile la vue est toujours la liste (`viewType` par défaut = `table`).
   - recherche **côté serveur**, relancée après 500 ms d'inactivité, repart à la page 1 (10 produits).
9. **Liste des produits** (vue « table » rendue en lignes empilées). Chaque ligne : padding `px-2 py-1.5` (8/6) ; fond `orange-50/60` si cochée, sinon blanc ; pas cliquable en elle-même. Deux colonnes (gauche / droite) :
   - **Case à cocher** 16×16 à gauche (bordure `gray-300`, accent orange).
   - **Vignette** 32×32 (`w-8 h-8`), radius 6, bordure `gray-100`, image du produit ; si aucune image : icône `Image` 32 grise sur fond `gray-50`.
   - **Nom du produit** : `text-[10px]` (10 px) semi-gras gris 900, tronqué, largeur max 120 px.
   - **Badge canal** à côté du nom : `text-[7px]` gras, `px-1`, radius complet : « **MAR.** » (fond `green-100`, texte `green-600`) si `isOnline !== false`, sinon « **POS** » (fond `blue-100`, texte `blue-600`).
   - **Seconde ligne (mobile uniquement)** : prix en orange brand `text-[9px]` gras (ex. « 12 345 FCFA ») ; séparateur « | » `text-[9px]` `gray-300` ; stock « **{stock} {unit}** » `text-[9px]` gras — **rouge (`red-500`) si stock < 10**, sinon gris (`gray-500`) ; si stock < 10, petite icône `AlertCircle` 9 px rouge après le stock.
   - **À droite** : si `canManageInventory`, bouton crayon `Edit` 16 dans une pastille `p-2.5` (10 px) fond `orange-50`, texte brand, radius 12 (ouvre la modale d'édition) ; puis chevron `ChevronRight` 18 gris clair (décoratif, non cliquable). **Aucun bouton supprimer sur la ligne mobile** : la suppression passe par la barre d'actions groupées (ou par le desktop).
   - Le badge de type produit de la colonne « Type » (Food / Marketplace / POS avec `Clock` / `ShoppingBag` / `Monitor`), la colonne catégorie, le prix détaillé, le stock, la note (`Star` + note + « (N) ») et les actions de la colonne de droite sont **desktop** (`hidden md:table-cell`) → EXCLUS.
10. **Chargement (squelettes)** — tant que la liste est vide et qu'une requête est en cours : 5 lignes de squelettes (petit carré 16, bloc 40×160, badges 24×80 / 24×96 / 24×64, bloc 32×64 à droite) avec animation shimmer grise. Remarque : ces lignes utilisent les classes `table-row` / `table-cell` sans préfixe (`display: table`) — rendu particulier à éviter en RN ; reproduire visuellement 5 lignes de cartes grises.
11. **État vide** — bloc centré padding 48 : icône `Package` 40 px à 20 % d'opacité, titre « **Aucun produit trouvé** » (`text-sm` semi-gras `gray-500`), sous-titre « **Essayez un autre terme ou élargissez vos filtres.** » (`text-xs`, gris clair).
12. **Pagination (« chargement infini » manuel)** — si `hasMore` : bouton centré dans un bloc padding 24 avec bordure haute : « **Voir plus de produits** » (`px-8 py-3`, fond blanc, bordure 2 px `gray-100`, radius 16, `text-sm` gras `gray-600`, icône `Plus` 16 orange) ; pendant le chargement : spinner `Loader2` 16 orange + libellé « **Chargement...** », bouton désactivé. Sinon, si `hasMore = false` et plus de 5 produits affichés : bandeau centré padding 32 « **Fin de l'inventaire** » (`text-[10px]` gras majuscules, letter-spacing large, `gray-400` à 50 % d'opacité). Taille de page = 10 ; `offset` = nombre de produits déjà chargés ; recherche, canal et flux de vertical sont envoyés au serveur à chaque requête ; le compteur total (`total`, fourni par le serveur) alimente la modale d'export/transfert et sert au calcul du plafond d'abonnement.
13. **Filtre vertical client** — en plus du filtre serveur, la liste est filtrée côté client : `all` = tout ; `shopping` / `food` selon `product.businessType` ou `mainCategory` contenant « Resto » ou « Alimentation ». Canal : `pos` = `isOnline === false`, `marketplace` = `isOnline !== false`, `all` = tout.

## Modales / feuilles / menus (une sous-section par modale : contenu exact, champs, boutons, validations)

### A. Modale produit — création / édition (3 étapes) — InventoryView

- **Conteneur** : overlay `slate-900/60` + flou ; panneau blanc radius 28, largeur pleine (max 768 px), hauteur max 92 % de l'écran ; en-tête collant, corps défilant, pied collant.
- **En-tête** : badge « **Modification** » (édition) ou « **Création** » (`px-2.5 py-0.5`, radius complet, `text-[10px]` très gras majuscules, fond `orange-100`, texte brand) ; texte « **Étape {n} sur 3** » (`text-xs` semi-gras gris 400) ; titre `text-lg` très gras : nom du produit en édition (ou « Modifier le produit » si vide), sinon « **Nouveau produit (boutique)** » si `isOnline` est vrai, sinon « **Nouveau produit (caisse)** » ; bouton fermer `X` 20 (padding 8, rond, hover gris).
- **Barre d'étapes** (3 boutons reliés par un trait gris horizontal, marges 32 px) : 1. `Package` « **1. Identité & Médias** », 2. `DollarSign` « **2. Tarifs & Stock** », 3. `Layers` « **3. Variantes** ». Cercle 36×36 : étape active = fond orange brand + ombre + ring `orange-50` + échelle 1,05 ; étape passée = fond `emerald-500` + icône `Check` 16 ; à venir = fond blanc + bordure 2 px `gray-200` + texte `gray-400`. Libellé `text-[10px]` gras (actif gris 900, passé `emerald-700`, sinon `gray-400`). Navigation : retour libre vers une étape antérieure ; aller à l'étape 2 exige un nom non vide ; aller à l'étape 3 exige nom non vide ET prix défini.
- **Étape 1 — Identité & Médias**
  - « Nom du Produit * » (libellé `text-xs` gras majuscules + icône `Tag`/`Package` 14 orange ; badge « **Requis** » orange `text-[10px]`) ; champ : fond `gray-50/80`, bordure 2 px `gray-200`, radius 16, `px-4 py-3`, `text-sm` semi-gras, placeholder exact « **Ex : T-shirt Oversize Bio, Burger Double Fromage, Robe d'été…** ». Obligatoire (étoile orange).
  - « Catégorie & Rayon » (icône `Tag` 14) : sélecteur natif groupé par rayon (`optgroup` = catégorie principale, options = sous-catégories). Source : `getProductCategoryTree(businessType)` (catégories actives en base, filtrées par vertical) ; repli sur `MAIN_CATEGORIES` / `CATEGORY_MAPPING` en dur si la table est vide (exclut « Restauration & Livraison Rapide », « Séjours… », « Produits Digitaux… » ; en food, seule « Restauration & Livraison Rapide »). Défaut : `category = 'Général'` (shopping) ou « Plats Cuisinés » (food), `mainCategory = 'Divers'` ou « Restauration & Livraison Rapide ». Changer la sous-catégorie recalcule `mainCategory` via le mapping.
  - « Description détaillée » (ligne de droite : « Recommandé pour la boutique », `text-[10px]` gris) : zone de texte 3 lignes, placeholder exact « **Décrivez votre produit : matière, caractéristiques, ingrédients, conseils d'utilisation…** », non redimensionnable.
  - « Photos du Produit » (icône `Image` 14 orange) + compteur « **N photo(s)** » (pastille grise `text-[10px]` gras). Zone en pointillés `gray-200`, padding 16 ; grille **3 colonnes** (mobile) `gap-3` : chaque photo = carré arrondi radius 12, bordure 2 px, image en couverture, bouton corbeille rouge 12 en haut à droite (visible en mobile), bandeau bas « **Principale** » (fond orange, `text-[9px]` blanc gras) sur la 1re image ; tuile « **+ Ajouter** » (bordure pointillée orange, fond `orange-50/40`, icône `Plus` 18 dans une pastille blanche, libellé `text-[9px]` gras). Limite **8 images** : au-delà, message d'erreur « Vous ne pouvez pas ajouter plus de 8 images. ». Les images sont optimisées côté web (`optimizeImage` + base64) → en mobile : choisir une image, la compresser, l'envoyer en base64/URL.
  - Note sous la grille (icône `Info` 12 orange) : « **La première photo est l'image principale. Vous pourrez aussi assigner des photos par variante à l'étape 3.** »
  - **Canal & visibilité** : carte dégradé orange clair / ambre, bordure orange clair ; pastille 40×40 radius 12 (fond orange brand si en ligne, gris sinon) avec icône `Globe` 20 (en ligne) ou `Monitor` 20 (caisse) ; titre `text-sm` gras : « **Publier sur la boutique en ligne** » ou « **Disponible uniquement en Caisse (POS)** » ; sous-texte `text-xs` gris : « **Visible publiquement par vos clients sur votre catalogue web** » ou « **Usage interne : encaissement sur place uniquement** » ; interrupteur 48×24 (piste orange brand ou `gray-300`, pastille blanche 16) qui bascule `isOnline`.
- **Étape 2 — Tarifs & Stock**

  - « Stock Initial Disponible » (icône `Package` 14) : champ numérique, placeholder « 0 » ; note dynamique : « **Des variantes existent : le stock total sera calculé depuis vos déclinaisons.** » si variantes, sinon « **Quantité totale disponible en réserve ou rayon.** »
  - « Unité de vente » (**shopping uniquement**, icône `Tag` 14) : sélecteur avec groupes « Standard » (Pièce, Unité (u), Douzaine, Paquet, Carton, Boîte / Box, Sac, Bouteille, Lot), « Poids & Mesures » (Kilogramme (kg), Gramme (g), Litre (L), Mètre (m), Mètre Carré (m²)), « Services & Événements » (Service / Forfait, Ticket / Entrée, Heure, Jour) et l'option « **Autre (Saisie libre)...** » ; si personnalisé : champ texte (placeholder « **Ex: Pack de 100, Fagot, Palette, Flacon...** », bordure orange) + mention « **Tapez l'unité personnalisée de votre choix** » (`text-[10px]` orange gras). Défaut « pièce ».
  - « Durée de Livraison / Préparation » (icône `Clock` 14) : sélecteur avec option vide « **Sélectionnez une durée indicative...** », groupe « Restauration & Immédiat » (15 minutes, 30 minutes, 45 minutes, 1 heure), « Livraison Express & Rapide » (24 heures (1 jour), 48 heures (2 jours), 72 heures (3 jours)), « Livraison Standard & Sur-Mesure » (3 à 5 jours, 1 semaine, 2 semaines, Sur commande / Fabrication sur-mesure).

À l'activation : palier initial `{ minQty: 50, prix total = arrondi(prix × 50 × 0,85), unitPrice = arrondi(prix × 0,85) }`. Liste des paliers (carte grise) : en-tête « **Paliers de gros configurés (N)** » (`text-[10px]` gras) + bouton « **+ Ajouter un palier** » (orange clair, icône `Plus` 12) ; chaque palier = carte blanche bordure grise radius 12, padding 12 : numéro « **#n** » (carré 24 orange clair), champ « **Dès (qté min)** » (numérique, min 2, placeholder « 50 », largeur 112 px), champ « **Prix total du lot (XOF)** » (numérique, suffixe « XOF », placeholder « 100000 », texte orange), bouton corbeille (`Trash2` 14, rouge au survol, aligné en bas) ; ligne de synthèse « **Soit : X / unité** » (gras noir) et, si économie > 0, « **Économie : −X FCFA** » + pastille verte « **−N%** ». Règle d'ajout : `minQty` suivant = +50 si ≥ 50 sinon ×2 ; remise 85 % pour le 1er palier, 75 % ensuite ; liste retriée par `minQty` ; les champs `wholesalePrice` / `wholesaleMinQty` reflètent toujours le premier palier.
- **Étape 3 — Variantes & Déclinaisons**
  - Bannière orange : pastille `Sparkles` 18 orange, titre « **Options & Déclinaisons du Produit** », texte « Ajoutez des options (ex : **Taille**, **Couleur**, **Format**) pour générer automatiquement vos variantes avec leur propre prix, stock et photo. »
  - Carte blanche bordure 2 px grise contenant le composant **VariantMatrixEditor** (voir section G).
  - Carte « **Aperçu avant enregistrement** » (icône `CheckCircle2` 14 verte + badge vert « **Prêt** ») : vignette 48 (1re image, sinon icône `Package`), nom du produit (ou « Sans titre »), ligne « **{catégorie} • En ligne** » ou « **{catégorie} • Caisse seule** », prix (intervalle min–max si des variantes ont un prix > 0, sinon prix de base, sinon « 0 FCFA ») et stock : « **N variante(s) (X en stock)** » (somme des stocks de variantes) ou « **X en stock** ».
- **Pied de modale** : bandeau d'erreur rose (icône `AlertCircle` 14 + texte + bouton `X` 12) affiché quand `submitError`. Boutons : « **Précédent** » (icône `ChevronLeft` 16, style fantôme, désactivé à l'étape 1 ou pendant l'envoi) ; « **Suivant** » (fond noir, texte blanc, `ChevronRight` 14 à droite) tant que l'étape < 3 ; « **Enregistrer le produit** » (fond orange, spinner + « **Enregistrement...** ») à l'étape 3.

Succès : « **Produit ajouté avec succès !** » ou « **Produit mis à jour avec succès !** » (remplacé par le 1er avertissement serveur s'il y en a un) ; la fiche est insérée en tête de liste ou remplacée sur place.

### B. Modale « Limite de produits atteinte » — InventoryView

- Déclenchée à l'ouverture d'une **création** (pas en édition) quand `localProducts.length >= plan.features.maxProducts` (défaut 6 si abonnement inconnu).
- Overlay `slate-900/60` + flou, z-300, panneau blanc radius 32, max 448 px, centré, padding 32–40, contenu centré : carré 80 `orange-50` bordé orange contenant `Award` 40 légèrement incliné ; titre `text-xl` gras « **Limite de produits atteinte !** » ; texte (`text-sm` gris) : « Vous avez atteint la limite de **{N} produits** pour votre abonnement actuel. » puis « Passez à la formule **Pro** pour continuer à développer votre inventaire. »
- Boutons empilés pleine largeur : « **Découvrir les Tarifs** » (orange plein, `ChevronRight` 18) → navigation vers l'abonnement (le web clique l'entrée de menu `[data-view-id="subscription"]` sinon redirige `/dashboard?view=subscription` ; en mobile : écran Abonnement) et ferme la modale ; « **Plus tard** » (texte seul gris) ferme la modale.

- Corps (défilant, max 75 % de hauteur) :

## Permissions

- `canManageInventory` (rôle vendeur) conditionne : l'affichage de la barre d'actions groupées, les boutons « Importer » / « Transférer », les boutons « + POS » / « + Store & POS », le bouton crayon de chaque ligne, les actions de la grille (desktop) et les boutons supprimer (desktop) ; l'accès aux modales import/transfert et à la modale produit.
- **Toujours autorisé** même sans droit d'inventaire : la consultation de la liste, la recherche, les filtres, les onglets de flux, la pagination et le bouton « Exporter » (+ modale d'export).
- `userRole` est transmis mais jamais lu ; `subscription` ne sert qu'au plafond de produits de la modale « Limite atteinte ».
- Côté serveur : `requireStoreAccess` sur chaque action ; les actions de suppression/écriture vérifient aussi les droits (erreur renvoyée dans `error`).

- Divers « md: » de la modale produit : titres `md:text-2xl`, cercles d'étapes 44 px, espacements `md:p-8`, `md:px-8`, boutons `md:px-4 md:py-2.5`, suffixes `md:text-sm`, etc.
- Grille photos de la modale produit en 4–5 colonnes (`sm:grid-cols-4 md:grid-cols-5`) → 3 colonnes en mobile.
- Modales : paddings `md:p-6`, tailles de titres `md:text-xl`, grilles `sm:grid-cols-2` / `sm:grid-cols-3` → 1 colonne en mobile (sauf les `grid-cols-3` sans préfixe : visibilité import, ajustements tarifaires, résultats, qui restent à 3 colonnes).
- `hidden sm:flex-row`, `sm:flex-nowrap`, `sm:justify-end`, `sm:items-center` divers (comportements desktop).

## Points ambigus / à vérifier

1. **Vue grille non atteignable en mobile** : la grille (cartes 2 colonnes) n'apparaît que via la bascule desktop. Faut-il la porter quand même (décision produit) ou garder uniquement la liste, comme le rendu mobile web ?
2. **Chargement infini** : le web charge par bouton « Voir plus de produits » (10 par lot) et non par détection de fin de scroll. Faut-il un `onEndReached` en mobile (déclenchement automatique) tout en gardant le libellé « Voir plus de produits » comme état d'erreur/manuel ?
3. **Recherche** : debounce 500 ms puis appel serveur (page 1) ; en mobile, prévoir une annulation de requête et un état vide dédié pendant la frappe.
4. **Squelettes de chargement** : les 5 lignes du web utilisent des classes `table-row` / `table-cell` sans préfixe (rendu tableau en mobile) — incohérence visuelle à trancher (5 cartes grises équivalentes recommandées).
5. **Sélection / suppression unitaire** : en mobile, aucune ligne n'expose de bouton supprimer ; la seule voie est la barre groupée (1 produit cochable). Confirmer que c'est bien le comportement attendu et non un oubli du web.
6. **Photos de produit** : le web accepte 8 photos (optimisation canvas + base64). En RN, prévoir caméra/galerie + compression et vérifier la taille acceptable par `saveProductAction` (payload JSONB base64 volumineux).
7. **`unit` en base64/unités personnalisées** : liste d'unités codée en dur dans la vue ; la valeur personnalisée est un texte libre (pas de validation).
8. **`wholesaleTiers`** : calculs d'économie locaux (0,85 / 0,75) — reproduire exactement, sinon les prix de gros affichés diffèrent.
9. **Taxonomie** : si `getProductCategoryTree` renvoie vide (table non peuplée), le web retombe sur les constantes historiques `MAIN_CATEGORIES` / `CATEGORY_MAPPING` ; l'app mobile doit embarquer le même repli pour un rendu identique.
10. **Barre groupée en bas** : `bottom-6` fixe sans compensation du clavier ni de la safe-area ; à adapter (`useSafeAreaInsets`) sans changer le style.
11. **Modale « Limite de produits »** : le web navigue vers l'abonnement (`/dashboard?view=subscription`) ; en mobile il faut définir la route/écran cible (écran Abonnement à créer ?).
12. **`userRole` / `storeName`** : `userRole` inutilisé (à ignorer) ; `storeName` par défaut « Boutique » si absent.
13. **Export / import de fichiers** : le web télécharge/ouvre des fichiers locaux ; en RN, il faut `expo-document-picker` + `expo-sharing` (ou `expo-file-system`) et vérifier que les modèles CSV restent exploitables.
14. **`product.rating` / `reviewCount`** : affichés uniquement en desktop ; inutiles en mobile (mais présents dans les données).
15. **Regroupement vertical côté client** : la détection food se fait aussi via `mainCategory` contenant « Resto » ou « Alimentation » — à conserver pour que les filtres donnent les mêmes résultats qu'en web.
16. **Zones non spécifiées** : pas de tri utilisateur (ordre serveur = `createdAt` décroissant), pas de sélection multiple par glissement, pas de `pull-to-refresh` sur le web.
